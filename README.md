# finbasic: a basic R package, explained

`finbasic` contains two financial functions:

- `loan_payment(principal, rate, years)`: monthly payment of a fixed-rate loan
- `npv(rate, cash_flows)`: net present value of a series of cash flows

This README explains every file of the package, then every step of the
process: from writing the code to sharing the package.

---

## Part 1: The files

```
finbasic/
├── DESCRIPTION
├── NAMESPACE              generated by roxygen2
├── LICENSE
├── README.md
├── .Rbuildignore
├── R/
│   └── finbasic.R
├── man/                   generated by roxygen2
│   ├── loan_payment.Rd
│   └── npv.Rd
└── tests/
    ├── testthat.R
    └── testthat/
        └── test-finbasic.R
```

You write four kinds of files: `DESCRIPTION`, `R/`, `tests/` and the
`#'` comments inside `R/`. roxygen2 generates the other two from those
comments: `NAMESPACE` and `man/`.

### 1.1 `DESCRIPTION`: the package description

This file tells R what the package is. Its presence is what makes a
folder an R package.

```
Package: finbasic
Type: Package
Title: Basic Financial Functions
Version: 0.1.0
Authors@R: person("Mohamed", "Miled", role = c("aut", "cre"),
    email = "mohamed.miled1982@gmail.com")
Description: Basic financial functions: monthly payment of a fixed-rate loan
    and net present value of cash flows.
License: MIT + file LICENSE
Encoding: UTF-8
Roxygen: list(markdown = TRUE)
RoxygenNote: 7.3.1
Suggests: testthat (>= 3.0.0)
Config/testthat/edition: 3
```

| Field | Meaning |
|---|---|
| `Package` | the name used in `library(finbasic)` |
| `Title` | one line, in Title Case, without a final full stop |
| `Version` | MAJOR.MINOR.PATCH; increase it at each release |
| `Authors@R` | authors and roles: `aut` = author, `cre` = maintainer |
| `Description` | one paragraph; continuation lines are indented |
| `License` | `MIT + file LICENSE` means MIT, with the details in `LICENSE` |
| `Encoding` | the text encoding of the files |
| `Roxygen`, `RoxygenNote` | roxygen2 settings; `markdown = TRUE` allows markdown in `#'` comments |
| `Suggests` | packages needed only for tests or examples, not by users |
| `Config/testthat/edition` | use testthat's current behaviour (edition 3) |

The package needs no other package to run, so there is no `Imports:` field.
If it used dplyr, you would add `Imports: dplyr`, and R would install dplyr
together with `finbasic`.

The format matters: one `Field: value` per line, continuation lines
indented. `R CMD check` reports any error in it.

### 1.2 `R/finbasic.R`: the functions

Every `.R` file in the `R/` folder is loaded with the package. Here,
one file holds both functions.

```r
#' Monthly payment of a fixed-rate loan
#'
#' @param principal Amount borrowed.
#' @param rate Annual interest rate as a decimal (0.045 for 4.5%).
#' @param years Term of the loan in years.
#' @return The fixed monthly payment.
#' @examples
#' loan_payment(200000, 0.045, 25)
#' @export
loan_payment <- function(principal, rate, years) {
  if (principal <= 0 || years <= 0 || rate < 0) {
    stop("principal and years must be positive, rate must be 0 or more")
  }
  n <- years * 12
  r <- rate / 12
  if (r == 0) {
    return(principal / n)
  }
  principal * r / (1 - (1 + r)^-n)
}
```

The lines starting with `#'` are **roxygen2 comments**. They document the
function, and roxygen2 converts them into the help page and the export list.

| Tag | Role |
|---|---|
| first line | the title of the help page |
| `@param` | one line per argument |
| `@return` | what the function returns |
| `@examples` | code run by `example(loan_payment)` and by `R CMD check` |
| `@export` | makes the function available after `library(finbasic)` |

A function without `@export` stays internal: the package can use it,
but users cannot call it with `library(finbasic)`.

In the code itself:

- `stop(...)` stops with a clear message on invalid input.
- `if (r == 0)` handles an interest-free loan, where the formula would
  divide by zero.
- The last expression is the value returned; `return()` is needed only
  to leave the function early.

In `npv`, `seq_along(cash_flows) - 1` gives the periods 0, 1, 2...
R vectors start at 1, so the `- 1` makes the first cash flow period 0.
The calculation is vectorised: `sum(cash_flows / (1 + rate)^t)`
discounts every cash flow at once, without a loop.

### 1.3 `NAMESPACE`: the export list (generated)

```
# Generated by roxygen2: do not edit by hand

export(loan_payment)
export(npv)
```

- One `export()` line per function marked `@export`.
- roxygen2 writes this file. **Do not edit it by hand**: your changes
  would be overwritten by the next `devtools::document()`.

### 1.4 `man/`: the help pages (generated)

- One `.Rd` file per documented function: `loan_payment.Rd`, `npv.Rd`.
- They are what `?loan_payment` displays.
- roxygen2 writes them from the `#'` comments. **Do not edit them by
  hand**: change the comments, then run `devtools::document()`.

### 1.5 `tests/`: the tests

Two files, two roles.

`tests/testthat.R` starts the tests during `R CMD check`:

```r
library(testthat)
library(finbasic)

test_check("finbasic")
```

You write this file once and never change it.

`tests/testthat/test-finbasic.R` holds the tests themselves:

```r
test_that("loan_payment gives the known value", {
  expect_equal(loan_payment(200000, 0.045, 25), 1111.66,
               tolerance = 0.005 / 1111.66)
})

test_that("loan_payment rejects bad input", {
  expect_error(loan_payment(-1, 0.05, 10))
})
```

- testthat runs every file named `test-*.R` in `tests/testthat/`.
- Each `test_that("description", { ... })` block is one test.
- `expect_equal(actual, expected)` compares two values. Its `tolerance`
  is **relative**: `0.005 / 1111.66` allows a difference of 0.005.
- `expect_error(...)` checks that the code **does** stop with an error.
  The test fails if no error occurs.

### 1.6 `LICENSE`, `.Rbuildignore` and `README.md`

`LICENSE` holds two lines, the format R expects with `MIT + file LICENSE`:

```
YEAR: 2026
COPYRIGHT HOLDER: Mohamed Miled
```

`.Rbuildignore` lists files to leave out of the built package, one
regular expression per line:

```
^README\.md$
```

- `README.md` is useful on GitHub but not inside the installed package.
- Without this line, `R CMD check` would report it as a non-standard file.

`README.md` is this file: the documentation shown on GitHub.

## Part 2: The process, step by step

### Step 1: Install the development tools

Once, in R:

```r
install.packages(c("devtools", "roxygen2", "testthat", "usethis"))
```

| Package | Role |
|---|---|
| `devtools` | install, load, test and check packages |
| `roxygen2` | turns `#'` comments into `NAMESPACE` and `man/` |
| `testthat` | the testing framework |
| `usethis` | creates the files of a new package |

`finbasic` contains only R code, so no compiler is needed. Rtools on
Windows, or Xcode on Mac, is required only for packages with C or C++ code.

### Step 2: Create the package skeleton

For a new package, usethis creates the folder, `DESCRIPTION`, `NAMESPACE`
and `R/` in one call:

```r
usethis::create_package("~/projects/finbasic")
```

In RStudio, this also opens the package as a project. Then:

```r
usethis::use_mit_license()     # creates LICENSE, updates DESCRIPTION
usethis::use_testthat(3)       # creates tests/testthat.R and tests/testthat/
usethis::use_test("finbasic")  # creates tests/testthat/test-finbasic.R
```

For this package, the files already exist: open the `finbasic` folder
as an RStudio project, or set it as the working directory with `setwd()`.

### Step 3: Write the code and its documentation

- Put the functions in `R/finbasic.R`.
- Add the `#'` comments above each function, with `@export` on the
  public ones.

### Step 4: Generate the documentation

```r
devtools::document()
```

This reads the `#'` comments and writes `NAMESPACE` and the `man/*.Rd`
files. Run it again after every change to the comments.

### Step 5: Load the package while developing

```r
devtools::load_all()
```

- Loads the current code as if the package were installed.
- Run it after each change; there is no need to reinstall.
- RStudio shortcut: Ctrl + Shift + L (Cmd + Shift + L on Mac).

### Step 6: Run the tests

```r
devtools::test()
```

Expected output:

```
[ FAIL 0 | WARN 0 | SKIP 0 | PASS 4 ]
```

RStudio shortcut: Ctrl + Shift + T.

### Step 7: Check the whole package

```r
devtools::check()
```

`R CMD check` is R's full quality control. It:

- validates `DESCRIPTION`;
- checks that every exported function is documented;
- runs the `@examples`;
- runs the tests.

The goal is:

```
0 errors ✔ | 0 warnings ✔ | 0 notes ✔
```

RStudio shortcut: Ctrl + Shift + E.

### Step 8: Install the package

```r
devtools::install()
```

Now, from any R session or script:

```r
library(finbasic)

loan_payment(200000, 0.045, 25)      # 1111.665
npv(0.10, c(-1000, 300, 400, 500))   # -21.03681
?loan_payment                        # the help page
```

### Step 9: Release a new version

1. Change the code and the `#'` comments.
2. Run `devtools::document()`, then `devtools::check()`.
3. Increase `Version:` in `DESCRIPTION`:
   - `0.1.0` → `0.1.1` for a bug fix;
   - `0.1.0` → `0.2.0` for a new function;
   - `0.1.0` → `1.0.0` for a change that breaks existing code.

### Step 10: Build the package file

```r
devtools::build()
```

This creates `finbasic_0.1.0.tar.gz` next to the package folder: the
source package, the format R uses to install and to share.
From a terminal, `R CMD build finbasic` does the same.

### Step 11: Share the package

**Option A: send the file.** The recipient runs:

```r
install.packages("finbasic_0.1.0.tar.gz", repos = NULL, type = "source")
```

**Option B: GitHub.** Push the folder to a repository; anyone installs with:

```r
remotes::install_github("YOUR-USERNAME/finbasic")
```

**Option C: CRAN**, so that `install.packages("finbasic")` works everywhere:

1. Run the stricter CRAN check, and fix every error, warning and note:
   ```r
   devtools::check(cran = TRUE)
   ```
2. Submit:
   ```r
   devtools::submit_cran()
   ```
3. Confirm the submission from the email CRAN sends to the maintainer.
4. A CRAN volunteer reviews the package before publication.

Unlike PyPI, CRAN reviews every package and re-checks it on several
operating systems. A package must keep passing those checks to stay on CRAN.

## Part 3: Common problems

| Message | Cause | Fix |
|---|---|---|
| `could not find function "npv"` | the package is not loaded, or `npv` lacks `@export` | `library(finbasic)`; or add `@export`, then `devtools::document()` |
| A change to `#'` comments has no effect on `?npv` | the documentation was not regenerated | `devtools::document()` |
| `Undocumented code objects` in `check()` | an exported function has no `#'` documentation | add the roxygen comments, then `devtools::document()` |
| `Non-standard file/directory found at top level` | a file such as `README.md` is not listed in `.Rbuildignore` | `usethis::use_build_ignore("README.md")` |
| `Malformed Description field` | a line in `DESCRIPTION` is not indented or not in `Field: value` form | fix the formatting; `check()` names the field |
